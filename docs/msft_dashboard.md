# Дашборд MSFT и рабочее обновление

Интерфейс предназначен для исследования точности прогноза одной акции. Он показывает результаты замороженного эксперимента и отдельную обновляемую оценку. Реализация — Streamlit и Plotly; данные и модели доступны локально.

## Установка и запуск

Проверенное окружение — Python 3.12.8. Из корня репозитория:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dashboard.lock.txt
```

Если эксперимент ещё не подготовлен, сначала выполнить загрузку и обучение из [README](../README.md) и [протокола](msft_experiment.md). Git содержит код и сводные результаты; SQLite, полные тексты, снимки признаков и файлы моделей остаются локальными. Новая загрузка источников может отличаться от исходного снимка — это не обещание побитового воспроизведения старых метрик на другом компьютере.

Для подготовленного эксперимента:

```powershell
.\run_msft.ps1
```

Открыть http://127.0.0.1:8501. Сервер слушает только локальный адрес; остановка — Ctrl+C в терминале. Команда последовательно строит объяснения, считает рабочую оценку по базе и запускает интерфейс. `-Refresh` добавляет сетевое обновление источников перед рабочим расчётом; `-PrepareOnly` выполняет подготовку без сервера. Расписания нет: обновление запускается командой или кнопкой.

Отдельные команды:

```powershell
.\.venv\Scripts\python.exe scripts/explain_msft.py
.\.venv\Scripts\python.exe scripts/update_msft.py --refresh
.\.venv\Scripts\python.exe -m streamlit run scripts/dashboard_msft.py --server.address 127.0.0.1 --server.port 8501
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Без `--refresh` команда update использует локальную базу и помечает это в результате. Если нужных закрытых сессий не хватает, расчёт останавливается на проверке календаря. При недоступности источника выводится ошибка, предыдущая рабочая оценка сохраняется. Интерфейс можно запустить отдельной командой и смотреть сохранённый эксперимент даже при сбое обновления.

## Вопросы аналитика

| Вкладка | Вопрос и действие |
|---|---|
| Прогноз и качество | Насколько прогноз близок к факту, когда ошибается сильнее? Выбрать период, сопоставить цены и ошибки, скачать CSV. Полная таблица семи вариантов относится ко всему test и не меняется фильтром. |
| Разбор прогноза | Почему Ridge дал эту цену? Выбрать любую поддерживаемую дату, увидеть вклады, исходные значения и точную проверку суммы. |
| Влияние признаков | Какие признаки заметны и полезны для точности, меняется ли картина по периодам? Выбрать одну из фиксированных половин года, сравнить два метода важности и изменить признак на PDP. |
| Данные и обновление | Какие данные лежат в основе исследования и когда создан новый расчёт? Проверить ограничения, временные границы, обновить оба источника и рабочую модель. |

Общий фильтр дат относится к первым двум вкладкам. Важность рассчитана для полного test и двух фиксированных половин. Пустой или обратный интервал сопровождается пояснением. Основной прогноз — последнее закрытие; сравнение с Ridge в интерфейсе не скрывает его меньшую точность на полном test.

## Разделение исследования и эксплуатации

Исследовательская модель обучена только на train+validation; тестовые прогнозы, параметры выбора и хеш снимка зафиксированы. Кнопка обновления не вызывает повторный выбор моделей и не меняет этот эксперимент.

Рабочая оценка использует текущую базу по предыдущему календарному дню Нью-Йорка, календарь NASDAQ и тот же расчёт признаков. Ridge с уже выбранным alpha переобучается на всех известных размеченных сессиях. Его рабочая копия хранится отдельно: `models/msft_live/ridge.joblib`. Основным прогнозом остаётся последнее закрытие. Рабочий результат — `data/processed/msft_live/latest.json`; журнал успешных и неуспешных запусков — `runs.jsonl` в том же каталоге.

Показаны целевая сессия, последняя свеча, конец обучения, фактическое время формирования и источник данных: свежая загрузка или локальная база. До номинальной отсечки 09:00 Нью-Йорк расчёт предварительный; после неё он явно помечен как поздний. Поздний запуск не выдаётся за прогноз, опубликованный заранее. Текущие исправления котировок и редакции текстов остаются ограничением.

## Проверка 16 октября 2026 года

31 автоматический тест пройден. В том числе проверены смена дат, разбор выбранного прогноза, переключение периода важности и PDP, отсутствие торговых сессий в фильтре и сообщение о сбое обновления. UI-тесты используют официальный [Streamlit AppTest](https://docs.streamlit.io/develop/api-reference/app-testing/st.testing.v1.apptest); при отсутствии UI-зависимостей или подготовленного эксперимента эти три интеграционные проверки пропускаются.

Сетевое обновление выполнено успешно; рабочая модель обучена по 15.10.2026 для оценки закрытия 16.10.2026. Расчёт создан после номинальной отсечки и так обозначен. Исходный исследовательский протокол и модели сохранены. Визуальная проверка проводится в браузере; тема явно задана в `.streamlit/config.toml`.

Проверка полного развёртывания на чистом окружении остаётся отдельным этапом. [Технические методы объяснений и результаты](msft_interpretability.md).
