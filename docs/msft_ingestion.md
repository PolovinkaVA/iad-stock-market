# Загрузка и хранение MSFT

Команды запускаются из корня проекта. Нужен Python 3.10+ и база часовых поясов IANA; на Windows она устанавливается командой `python -m pip install tzdata` и включена в `requirements.txt`. Конфигурация — `config/msft.json`. Все пути в ней отсчитываются от корня проекта.

## Первый запуск и обновление

На новом компьютере, без локального кэша:

```powershell
python scripts/ingest_msft.py --end 2026-10-15
```

Команда скачивает историю котировок с 2018 года и последовательно обходит архив пресс-релизов до начала периода. Источники запрашиваются с паузой; первая загрузка занимает несколько минут. Сырые ответы и тексты сохраняются локально, в Git публикуются код и сводки проверок.

На компьютере, где уже выполнялся аудит, можно сначала импортировать его снимок без сетевых запросов:

```powershell
python scripts/ingest_msft.py --import-audit --end 2026-10-13
python scripts/ingest_msft.py --end 2026-10-15
```

Импорт проверяет SHA-256 каждого исходного ответа по метаданным аудитора. Повреждённый файл не принимается. Переносы строк, добавленные текстовым режимом Windows, восстанавливаются до сверки хеша. Повторный импорт не создаёт новые версии одинаковых данных.

Регулярное обновление:

```powershell
python scripts/ingest_msft.py
```

Без `--end` загружаются данные по вчерашний день в Нью-Йорке включительно; текущая дневная свеча исключена. Это консервативная граница загрузки, а не уже утверждённая временная схема прогнозирования.

## Инкрементальность и ревизии

- Котировки загружаются от последней сохранённой даты с перекрытием 7 календарных дней. Старые значения сохраняются версиями. Запрашиваются также adjusted close и события дивидендов/дроблений; их наличие ещё не означает завершённую проверку корпоративных действий.
- Архив просматривается от первой страницы до даты на 30 дней раньше последней известной публикации. Новые URL попадают в постоянную очередь. Неудачно загруженный текст остаётся в очереди и повторяется в следующем запуске, даже если вышел за окно обнаружения.
- За обычный запуск перепроверяется до 20 самых давно проверенных текстов, если прошло минимум 30 дней. При изменении текста, заголовка или дат появляется новая версия. Промежуточные редакции между запросами могут остаться неизвестными.
- Для каждой загрузки сохраняются время получения и связь с исходным ответом. Более старый импорт не заменяет текущую версию. Исходные ответы хранятся по хешу без перезаписи; таблицы `articles` и `prices` — представления последних наблюдавшихся версий.

Ограничение инкрементального режима: поздно добавленная в архив старая публикация за пределами окна обнаружения может не попасть в обычный обход; исторические исправления цен и пересчёт adjusted close тоже могут выходить за 7 дней. Перед фиксацией датасета и при проверке источников предусмотрен полный обход:

```powershell
python scripts/ingest_msft.py --full
```

Можно обновить только один источник, например всю историю цен и событий без повторного скачивания всех текстов:

```powershell
python scripts/ingest_msft.py --source prices --full --end 2026-10-15
python scripts/ingest_msft.py --source articles --full --end 2026-10-15
```

## Хранение и ошибки

База — `data/msft.sqlite`, исходные ответы — `data/raw/msft/`. Основные таблицы: `raw_responses`, `observations`, `article_queue`, `article_versions`, `price_versions`, `corporate_actions`, `runs`, `errors`. Файлы исходных ответов нужны вместе с базой для воспроизведения происхождения данных.

Ошибка одного источника не отменяет сохранённый результат другого. Тексты сохраняются отдельными транзакциями; ценовой ответ валидируется целиком до записи строк. Некорректные OHLCV, дубли дат, неожиданный тикер/валюта, отсутствующая дата публикации и дата без часового пояса отклоняются. Исходный некорректный ответ сохраняется для диагностики.

Сетевые таймауты, HTTP 429 и временные серверные ошибки повторяются до трёх попыток; HTTP 403 не обходится. Статусы журнала: `success`, `partial`, `failed`, `running`. Принудительно прерванный процесс может оставить `running`; следующий запуск безопасно повторяет незавершённую загрузку. Параллельные запуски CLI не нужны.

Код выхода 0 означает отсутствие зарегистрированных ошибок загрузки, 1 — частичный или полный сбой. Это не сертификат полноты данных по биржевому календарю. JSON-сводка сохраняется через `--report путь.json`; подробные ошибки доступны в таблице `errors` по `run_id`.

## Проверки и следующий шаг

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Проверки охватывают парсинг старой разметки, временные метки, проверку исходных хешей, идемпотентность, версии, приоритет более свежего наблюдения, отказ некорректного ценового пакета, частичный сбой и восстановление очереди, перекрытие дат и политику сетевых повторов.

Полный набор тестов использует зависимости из `requirements-msft.lock.txt`. Проверка календаря, обработка, признаки и обучение реализованы отдельно: [протокол эксперимента](msft_experiment.md), [результаты](msft_results.md). Ограничение текущих редакций текстов сохраняется.
