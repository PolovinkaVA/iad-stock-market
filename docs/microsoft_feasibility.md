# Проверка Microsoft: результат на 14 октября 2026 года

## Решение

**MSFT принят как рабочий вариант до согласования с преподавателем.** Техническая доступность котировок и текстового архива подтверждена. Допуск текущих версий текстов в строгую историческую проверку модели **не подтверждён**.

Это проверка источников, а не готовая прогнозная система. Модель MSFT не обучалась, точность не оценивалась. Результаты SBER нельзя переносить на MSFT.

## Проверенные источники

- Котировки: JSON дневных свечей Yahoo Finance, тикер MSFT, запрошен период 2018-01-01–2026-10-13.
- Тексты: https://news.microsoft.com/source/tag/press-releases/ — последовательно просмотрены 45 страниц, включая первую страницу целиком раньше начала исследуемого периода. Это полнота обхода данного тега на момент проверки, а не всех публикаций Microsoft или всего рынка.
- Найдено 526 уникальных URL за 2018-01-05–2026-10-07; все 526 страниц скачаны. Сырые HTML и котировки находятся только в локальном кэше `tmp/us_sources/audit_cache/`.
- В Git сохраняются код проверки, сводка и манифест с URL, датами, длинами и хешами; полные тексты и котировки не публикуются.

## Что подтверждено и что остаётся открытым

1. **Доступность:** без платного API получены многолетние котировки и тексты. Проверено извлечение текста из старой и новой HTML-разметки. Эти запросы не гарантируют постоянную доступность источника.
2. **Исторические версии:** одинаковая поздняя дата у 465 страниц совместима с переносом/массовым обновлением сайта, но это гипотеза. Метаданные не доказывают ни неизменность, ни содержательное редактирование текстов. Нельзя присвоить текущему тексту старую дату публикации и на этом основании заявить доказанное отсутствие утечки.
3. **Время:** хранить дату публикации как момент с часовым поясом; отдельно переводить в America/New_York. Дата в URL может относиться к другому часовому поясу. Два выявленных расхождения нельзя автоматически считать ошибками или исправлять под URL.
4. **Качество корпуса:** 30 страниц — уведомления о доступности отчётности. Их следует отделить от содержательных релизов и не считать независимыми подробными текстами отчётов. Проверка длины и точного хеша не выявляет все шаблонные или почти одинаковые тексты.
5. **Котировки:** выполнены проверки строк, но ещё не сверены биржевой календарь, корректировки цен, корпоративные действия и факт отсутствия пропущенных сессий. Результаты проверки не равны полной сертификации данных.
6. **Обновление:** свежий повторный запрос первой страницы дал 12 уже известных URL, новых записей 0. Проверена возможность обнаружения/дедупликации; полноценная инкрементальная загрузка, журнал и тесты отказов пока не реализованы.

## Следующие действия

- Подтвердить с преподавателем цель и дополнительные компоненты (вопросы в `teacher_questions_2026-10-16.md`).
- До моделирования утвердить протокол исторической доступности текстов: подтверждённые версии/обоснованный период; иначе отдельный ретроспективный эксперимент с ограничениями и строгая оценка без сомнительных текстов. Если это не соответствует ожиданиям преподавателя — заменить текстовый источник.
- Сохранять версии новых публикаций с момента получения. Не публиковать исходные тексты и котировки в репозитории.
- Доработать загрузчики, качество и единый расчёт признаков; только затем переходить к моделям и дашборду.

## Воспроизведение

Требуется Python 3.10+; скрипт использует только стандартную библиотеку.

```powershell
python scripts/audit_microsoft.py --end 2026-10-13
python scripts/audit_microsoft.py --end 2026-10-13 --offline --report tmp/us_sources/offline_audit.json
python -m unittest discover -s tests -v
```

Первый запуск обращается к источникам, повторные используют локальный кэш; первая страница архива в сетевом режиме дополнительно проверяется свежим запросом. Для нового снимка нужен отдельный сохранённый/переименованный каталог кэша, а не смешивание исторических версий. Кэш не включён в Git: другой компьютер может повторить сбор, но не гарантированно получить идентичные изменяемые страницы. Хеши позволяют выявить различия.

Машинные результаты: `reports/microsoft_audit.json`, `reports/microsoft_articles.csv`.

Проверка воспроизводимости выполнена: повторный аудит из кэша не сделал сетевых запросов, все содержательные результаты совпали, SHA-256 манифеста остался `9ce1f372cad87762f1ea6f85806200a4b41310b11f26904f4e610b7e8efb9b06`. Четыре проверки парсинга и временных меток прошли.
