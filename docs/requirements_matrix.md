# Контроль требований методички

Источник: «Работа на семестр ИАД_МИСИС.pdf», 8 страниц. Состояние на 2026-10-16 с учётом ответов преподавателя, переданных студентом. Эта таблица фиксирует план проверок; она не подтверждает готовность системы MSFT.

| Требование | Основание | Состояние и проверка |
|---|---|---|
| Область, конкретная цель, пользователь, регулярные данные | Раздел 2, с. 2–3 | MSFT и цена следующего закрытия согласованы; объём — признак. Сценарий аналитика описан в постановке. |
| Не менее двух разнородных источников, один слабоструктурированный | Раздел 3, с. 3 | Проверяются котировки JSON и корпоративные тексты HTML. Проверка источников не равна их включению в модель. |
| Инкрементальная загрузка | Раздел 3, с. 3–4 | Новый конвейер должен отслеживать новые даты/URL; аудит архива — разовая проверка, не готовый загрузчик. |
| Идемпотентность, устойчивость, журнал запусков | Раздел 3, с. 4 | Потребуются проверки повторной загрузки, отсутствия дубликатов, таймаута/ошибки, сохранения частичного результата. Кэш аудитора это полностью не заменяет. |
| Хранение исходных и обработанных данных | Раздел 1, с. 1 | В SBER есть SQLite и файлы. Для MSFT исходные ответы аудита сохранены локально; производственная схема и версии — следующий этап. |
| Очистка, пропуски, аномалии, качество | Раздел 3, с. 4 | Аудит проверяет OHLCV и извлечение текста. Нужны проверки календаря/корпоративных действий и правил очистки без будущих данных. |
| Обработка слабоструктурированных данных | Раздел 3, с. 4 | Извлечение текста проверяется. Векторизация/признаки и оценка полезности ещё не выполнены. |
| Лаги, окна, календарь, категории | Раздел 3, с. 4 | Часть есть в SBER. Для MSFT определить и обосновать категории, например тип события, и обучение кодировщиков только на train. |
| Единый расчёт признаков обучения и эксплуатации | Раздел 3, с. 4 | В SBER обнаружено дублирование расчёта. Нужна одна функция/конвейер и проверка совпадения на одной дате. |
| Отбор признаков и оценка влияния | Раздел 3, с. 4 | Для MSFT запланировано сравнение групп признаков на валидации. Тест не используется для выбора. |
| Отсутствие утечки, временное разбиение, seed | Раздел 3, с. 4 | Текущие тексты разрешены с описанием ограничения редакций, без поиска оригиналов. Нужны временные отсечки, проверки доступности цен/публикаций, обучение преобразований только на train и фиксация seed. Ограничение редакций не считается доказанно устранённым. |
| Минимум три модели, включая baseline; разные классы | Раздел 3, с. 4–5 | Предлагаются наивная, линейная регрессия, случайный лес. Модели MSFT ещё не обучены. |
| Единая временная валидация, минимум две метрики, понятные единицы | Раздел 3, с. 5 | План: MAE/RMSE в USD и сравнение с baseline; итоговая проверка на отложенном периоде. |
| Дашборд: факт, прогноз, качество; каждый элемент отвечает на вопрос | Раздел 3, с. 5; оценка, с. 8 | Имеется интерфейс SBER. Для MSFT нужен отдельный согласованный сценарий, фильтры и проверка обновления. |
| Компоненты по выбору | Раздел 4, с. 5–6; оценка, с. 8 | Преподаватель подтвердил достаточность полной интерпретируемости. Реализация всех четырёх требований направления ещё предстоит. |
| Интерпретируемость: два метода важности, отдельный прогноз, зависимость, периоды | Раздел 4, с. 5 | Требуется проверить все четыре пункта для выбранной модели и возможность объяснить произвольную поддерживаемую дату на защите. |
| Воспроизводимость, автоматизация, конфигурация, открытые данные | Раздел 5, с. 6–7 | Скрипт аудита использует стандартную библиотеку; кэш позволяет повторную проверку. Полный MSFT-конвейер ещё не реализован. |
| Репозиторий с историей, README, архитектура | Раздел 6, с. 7 | Исходный прототип опубликован; дальнейшая работа фиксируется по реальным этапам. Схемы аудитора и целевой системы добавлены. Отдельный дневник не требуется; история Git сохраняется. |
| Отчёт, презентация, работающий прототип, ЛМС | Раздел 6, с. 7–8; организационные уточнения 16.10 | Показы 13 и 27 ноября: презентация или отчёт. По ответам, переданным одногруппником: отчёт 30–40 страниц, защита до середины декабря; при выполнении всех промежуточных точек можно без устной защиты. Это условие пока не подтверждено для проекта. Точный срок и порядок сдачи в ЛМС неизвестны. Предварительные материалы SBER не являются итоговыми материалами MSFT. |

Мониторинг с переобучением и автоматизированный подбор/журнал экспериментов описаны в разделе компонентов по выбору. Их полные требования не следует автоматически объявлять обязательными для выбранного направления, но общие требования к качеству, воспроизводимости и фиксации параметров сохраняются.
