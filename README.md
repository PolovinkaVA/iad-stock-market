# Прогнозирование цены акций Microsoft (MSFT)

Семестровый проект магистратуры НИТУ МИСИС по дисциплине «Интеллектуальный анализ данных». Цель — разработать систему прогнозирования цены закрытия MSFT на следующий торговый день с автоматическим сбором данных, сравнением моделей, объяснением прогнозов и интерактивным дашбордом.

## Задача и данные

Для прогнозирования используются дневные котировки Yahoo Finance и тексты официальных пресс-релизов Microsoft. Объём торгов служит дополнительным признаком. Исследовательский вопрос — улучшают ли текстовые признаки прогноз по сравнению с использованием только рыночных данных.

Сравнены наивный прогноз «следующее закрытие равно последнему известному», регуляризованная линейная регрессия и случайный лес. Прогноз формируется в 09:00 по Нью-Йорку перед следующей сессией на основе предыдущей закрытой свечи и опубликованных к этому времени текстов. Оценка проводится с сохранением временного порядка по MAE и RMSE в долларах США. Отдельная часть проекта посвящена интерпретируемости моделей.

## Запуск проверки Microsoft

Команды выполняются из корня проекта. Для аудитора нужен Python 3.10+; дополнительных Python-пакетов он не требует.

```powershell
python scripts/audit_microsoft.py --end 2026-10-13
```

Первый запуск скачивает данные из внешних источников и может занять несколько минут. Он создаёт локальный кэш в `tmp/us_sources/audit_cache/` и отчёты:

- [Сводка проверок](reports/microsoft_audit.json).
- [Манифест публикаций: URL, даты, длины и хеши](reports/microsoft_articles.csv).

Повторная проверка **на компьютере, где уже есть кэш**:

```powershell
python scripts/audit_microsoft.py --end 2026-10-13 --offline --report tmp/us_sources/offline_audit.json
```

Сырые тексты и котировки хранятся локально. На новом компьютере сначала нужен сетевой запуск. Источники могут менять страницы, поэтому новая загрузка не обязана совпадать со снимком от 14 октября. Сохранённые хеши позволяют сравнить результаты. Для обновления базы используется отдельный загрузчик, описанный ниже.

## Загрузка данных MSFT

```powershell
python -m pip install tzdata
python scripts/ingest_msft.py --end 2026-10-15
```

Конфигурация — `config/msft.json`. На Windows нужен пакет `tzdata` (включён в `requirements.txt`). Первый сетевой запуск скачивает историю, следующие догружают данные с перекрытием. На компьютере с кэшем аудитора доступен импорт без сети: `python scripts/ingest_msft.py --import-audit --end 2026-10-13`. [Подробные команды и ограничения](docs/msft_ingestion.md).

Проверка 16 октября: [импорт](reports/msft_ingestion_import.json), [повтор без дублей](reports/msft_ingestion_replay.json), [полная история цен](reports/msft_ingestion_prices.json), [инкрементальное обновление](reports/msft_ingestion_update.json), [целостность базы и сопоставление с аудитом](reports/msft_ingestion_checks.json). Все 526 хешей извлечённых текстов совпали с аудитом. При свежем запросе изменился объём одного прошлого дня и adjusted close у 1 467 строк (максимальное различие около 0,000183 USD); прежние значения сохранены версиями. Обычный close не изменился.

## Подготовка данных и обучение

Проверенное окружение — Python 3.12.8. Версии зависимостей зафиксированы в `requirements-msft.lock.txt`:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-msft.lock.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe scripts/prepare_msft.py
.\.venv\Scripts\python.exe scripts/train_msft.py --stage validate
.\.venv\Scripts\python.exe scripts/train_msft.py --stage test
```

Подготовка использует базу MSFT, заполненную предыдущей командой загрузки. Конфигурация — `config/msft_experiment.json`. Train: 01.02.2018–10.10.2024; validation: 11.10.2024–14.10.2025; test: 15.10.2025–15.10.2026. Словарь текста, масштабирование и категории обучаются только на train при выборе модели; перед итоговой оценкой — на train+validation. Test не используется для выбора.

Повторный запуск с сохранённым снимком воспроизводит подготовку; источники при новой загрузке могут измениться. Изменённые данные не перезаписывают замороженный эксперимент: для нового опыта нужны отдельные каталоги. [Подробности воспроизведения и ограничения](docs/msft_experiment.md).

## Ограничения исследования

Используются текущие редакции пресс-релизов с исходными датами публикации. Их содержание на историческую дату не подтверждено: поздние изменения страниц могут влиять на ретроспективную оценку. Даты публикации, изменения и загрузки сохраняются отдельно. Сравнение с моделью без текстов выполнено при этом допущении.

Корпоративные пресс-релизы отражают сообщения самой Microsoft и не охватывают весь новостной фон рынка. Историческая доступность исправленных котировок к 09:00 не измерена. Календарь проверен; в выбранном периоде нет дроблений, adjusted close исключён из модели. Оценка относится к одному временному разбиению, статистическая значимость небольших различий метрик не проверялась.


## Исходный прототип SBER

[Описание и команды запуска SBER](docs/sber_prototype.md). Команда `run_pipeline.ps1` и конфигурация `config/config.yaml` пока относятся именно к SBER. Запуск этой команды не обучает модель Microsoft.

Результаты SBER относятся к исходному прототипу; результаты MSFT представлены отдельно.
