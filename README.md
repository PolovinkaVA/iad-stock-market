# Прогноз цены акции SBER

Учебный проект по дисциплине «Интеллектуальный анализ данных»: прототип прогнозно-аналитической системы для оценки цены закрытия SBER на следующий торговый день.

## Текущий статус

Предварительный прототип SBER, полученный до начала ведения Git. Проект проходит аудит соответствия методичке; готовность к защите не подтверждена. Рассматривается переход на Microsoft (MSFT): история котировок доступна, проверены выборочные страницы официального архива пресс-релизов. Полнота текстового корпуса и корректность использования исторических версий требуют проверки.

Перечень ниже описывает прежние заявления о выполнении этапов, а не результаты независимой проверки. Основные открытые вопросы: полноценный слабоструктурированный источник, единый расчёт признаков, проверка воспроизводимости и выбор дополнительных компонентов. Локальные DOCX/PPTX являются предварительными материалами и пока не включены в репозиторий.

## Постановка задачи

- **Объект:** обыкновенные акции Сбербанка (тикер `SBER`, рынок акций MOEX).
- **Целевой показатель:** цена закрытия следующего торгового дня, руб.
- **Горизонт:** один торговый день.
- **Пользователь:** студент/аналитик, которому нужно просмотреть историю, прогноз и ошибку модели.
- **Источники:** исторические дневные свечи MOEX ISS и слабоструктурированные тексты официальных пресс-релизов Банка России из RSS.
- **Ограничение:** результат предназначен для учебного анализа, а не для инвестиционных рекомендаций.

Прогнозируем уровень закрытия, а не доходность: так качество ошибки можно прямо показать пользователю в рублях. Для сравнения используются наивный прогноз (следующее закрытие равно последнему известному) и три модели разных классов. Разделение train/validation/test хронологическое. Для каждой ML-модели набор признаков выбирается только на validation. Любой признак на дату *t* рассчитывается по данным, доступным к моменту прогноза на дату *t*.

## План работы

1. Постановка задачи и архитектура — выполнено.
2. Инкрементальная загрузка MOEX и новостей, хранение исходных данных и журналов запусков — выполнено. Используется официальный RSS Банка России.
3. Очистка, контроль качества, объединение источников и единый расчёт признаков — выполнено. RSS содержит 15 записей только за 11.09–08.10.2026, они назначены 11 торговым сессиям из 2 180 (0,50%). Поэтому новостные признаки сохраняются для анализа, но исключаются из исторического обучения.
4. Временная валидация, выбор групп признаков, базовая и ML-модели — выполнено на ценовых признаках. На валидации выбрана линейная регрессия с пятью ценовыми признаками (MAE 3,29 руб.); на отложенном тесте MAE 2,43 руб., MAPE 0,82%.
5. Интерпретация признаков и мониторинг исторической ошибки — выполнено. Сравнены наборы признаков, важность оценивается встроенным методом деревьев и permutation importance, влияние ключевых признаков показано через partial dependence. Для текущего прогноза добавлено локальное объяснение. Исторический мониторинг сохраняет ошибки по месяцам и скользящую MAE за 20 сессий.
6. Дашборд, автоматизированный запуск и инструкция воспроизведения — выполнено: `dashboard.py` и `run_pipeline.ps1`.
7. Обновлённые отчёт и презентация — `reports/Итоговый_отчет_SBER_обновленный.docx` и `reports/Презентация_к_защите_SBER_итог.pptx`. В них отражён отбор признаков по validation и пересчитанные результаты.

## Запуск

Из корневой папки проекта:

```powershell
python -m pip install -r requirements.txt
$env:PYTHONPATH = "src"
python -m stocks_forecast.ingest
python -m stocks_forecast.prepare
python -m stocks_forecast.modeling
python -m stocks_forecast.feature_analysis
streamlit run src/stocks_forecast/dashboard.py
```

В PowerShell три шага пересчёта можно выполнить одной командой `./run_pipeline.ps1`; для интерфейса затем запустите команду Streamlit из примера.

Команда `./run_pipeline.ps1` выполняет загрузку, подготовку данных, сравнение моделей и анализ признаков. Она создаёт `data/project.sqlite`. Таблицы `prices` и `news` содержат котировки и публикации; `ingestion_runs` хранит результат каждого запуска. Путь к базе, тикер, даты и параметры запросов настраиваются в `config/config.yaml`. Повторная загрузка котировок обновляет перекрывающиеся последние даты, а новости дедуплицируются по URL. RSS содержит публичные пресс-релизы Банка России и может охватывать более короткий период, чем котировки; это ограничение измеряется перед сравнением моделей.

Если один из источников недоступен или ограничивает частоту запросов, загрузчик повторит запрос и запишет ошибку в `ingestion_runs`; данные успешно обработанного источника при этом сохраняются.

Подготовка создаёт `data/processed/features.csv` и `data/processed/quality_report.json`. В строке торговой сессии признаки используют только цены, известные к её закрытию; целевая колонка `target_close_next` содержит цену закрытия следующей сессии. День недели, месяц и день месяца кодируются парами sin/cos, что сохраняет циклическую близость соседних календарных значений. Скачивание данных и подготовка запускаются тем же кодом и при обучении, и при обновлении прогноза.

Сравнение сохраняет `reports/model_comparison.json` и `reports/model_comparison.csv`. `reports/feature_analysis.json` содержит сравнение групп признаков на validation, permutation importance для разных периодов, встроенную важность деревьев и частичную зависимость прогноза от ключевых признаков. Тестовая важность рассчитывается после выбора модели и не участвует в отборе. `reports/test_predictions.csv` содержит прогнозы и ошибки теста, а `reports/monitoring.json` — помесячную и скользящую MAE. Новостные признаки включаются только при покрытии не менее 20% обучающей таблицы: текущий RSS покрывает 0,50%, поэтому они исключены. Выбрана линейная регрессия с пятью ценовыми признаками; её MAE на отложенном тесте — 2,43 руб. (MAPE 0,82%). Порог мониторинга — повод проверить модель, а не доказательство дрейфа; это историческая оценка, не торговая доходность.
